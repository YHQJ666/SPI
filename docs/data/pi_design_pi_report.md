# SFRA 扫频 → PI (KDC, fz0) 设计结果

- 数据：`SFRAData.csv`，100 点，100–5000 Hz，fs = 20 kHz
- 模式：Series PI (Pole Zero)，Gc = KDC·(1 + ωz/s)
- 约束：fc ∈ [0.5, 2000] Hz，GM ≥ 5.0 dB，PM ∈ [45, 60]°
- 判据：与 Compensation Designer 状态栏一致 —— 逐采样点找**第一次** 0 dB 穿越 / 第一次 −180° 穿越

## 参数

| 参数 | 值 |
|---|---|
| **KDC** | **0.024499** |
| **fz0** | **5.708 kHz** |
| 穿越频率 fc | 989.39 Hz |
| 相位裕度 PM | 57.57° |
| 幅值裕度 GM | 5.22 dB @ 2096 Hz |

GUI 状态栏应显示：`Folg_cf 0.98939 kHz  Gain Margin 5.22 dB  Phase Margin 57.57 Degrees`

0 dB 穿越（任意方向）共 1 次；GUI 只认第一次“由正到负”的穿越。

模拟 PI：Kp = KDC = 0.024499，Ki = 878.7 rad/s；Tustin 离散（20 kHz）：C1 = 0.046465，C2 = -0.002532，u(k)=u(k−1)+C1·e(k)+C2·e(k−1)

## 为什么 fc 上不去 ~1 kHz

1. Plant 在 800 Hz–2 kHz 的幅值几乎不降（16.5 → 18 dB），环路的 −20 dB/dec 主要靠 PI 的积分段提供。
2. 要把 PM 压到 45–60°，零点必须落在 fc 附近或 fc 之上（fz0 ≈ 0.3–0.6·fc）；这时 comp 在 2.1–2.4 kHz 已贡献 −60~−75°，−180° 穿越点被拉到 2.1–2.4 kHz，而 plant 在那里还有 17.5 dB，GM 只剩 3.6–4.3 dB。
3. 反过来把 GM 做高只能减小 KDC，fc 随之下移。所以 GM ≥ 5 dB 把 fc 卡在 ~1 kHz，再往上要么 GM < 5 dB，要么 PM > 60°。

## 注意

1. PM 45–60° 在这条 plant 上只能靠把零点放到 fc 之上（≈4–6 kHz）实现；零点放到 100–500 Hz 的“常规 PI”在 1 kHz 附近 PM 会到 110–130°。
2. GM 对 2.1–3 kHz 的相位很敏感（这段数据本身有卷绕/噪声，100 点里 2.76 kHz 处刚好翻过一次 ±180）。
3. 本结果按原始 CSV 算（GUI 就是这么用的）。文档里的 ZOH 校正（相位 +180·f/fs）会让 −180° 穿越点后移，GM 读数更高，不要和 GUI 混用。
4. fz0 接近 fs/4，双线性离散后等效零点约 4.6 kHz，实际数字环路 PM 会高 1–3°；上板后仍建议再扫一次 SFRA 复核。
5. 旧设计（0.134 / 0.4 kHz）在 GUI 里 PM 显示 121°，但 |L| 在 780 Hz 之后还反复穿越 0 dB（780–1070 Hz 间共 6 次，数据噪声），另有真实一次在 2.27 kHz、PM≈41°。GUI 只报第一次，别只看状态栏。本脚本推荐的解只有 1 次 0 dB 穿越。
